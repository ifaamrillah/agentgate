# M6 Git & PR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal (spec "Selesai bila"):** alur Dev → PR → Review → Testing (screenshot) → merge berjalan
end-to-end: job Dev di runner membuat branch tiket dari **base branch** repo, commit, push, lalu
server membuka PR lewat provider git; webhook PR/CI dari provider memperbarui status PR di tiket
dan memenuhi gate `pr_open` / `ci_green` / `prs_merged`; approve stage Code Review (mode merge
otomatis) me-merge PR.

**Spec:** `docs/spec.md` §"Git, code review, testing & deploy", §"Sinkronisasi aturan", baris M6.
Prototype: `screens-m4-m6.js` (Git provider, Konvensi git & deploy project, Pull request project),
`screens-m2-m3.js` (tab "PR & CI" tiket, badge PR di header). Utang: M3 (gate git selalu gagal),
M5 (`JobSpec` tanpa base branch, sinkron aturan via PR, `max_parallel` tidak ditegakkan).

## Cakupan M6 kali ini

Prinsip spec "satu alur utuh dulu (satu client, satu provider git)": **GitHub** (github.com dan
GitHub Enterprise Server yang terjangkau server) di belakang abstraksi `GitProvider`. GitLab,
Bitbucket, jembatan runner untuk server di balik firewall, komentar review AI per baris, environment
testing per repo, stage Deploy, dan jalur kode ke server dicatat sebagai utang (UI menampilkan
"segera").

## Architecture

- **Koneksi provider** (`git_connections`, per workspace, izin `ManageWorkspace`): `provider`
  (`github` | `github_enterprise`), `api_base` (`https://api.github.com` / `https://host/api/v3`),
  `web_base`, token (PAT/fine-grained) **terenkripsi** XChaCha20 (`ENCRYPTION_KEY`), `account`
  (login dari `GET /user`, diverifikasi saat simpan), `webhook_secret` terenkripsi (acak 32 byte).
  Satu koneksi per provider+host per workspace. Putuskan = hapus baris (repo kehilangan link).
  Keputusan sementara: token, bukan GitHub App (App perlu didaftarkan pemilik produk).
- **Abstraksi** `services::git::provider::GitProvider` (trait async): `whoami`, `repo`,
  `create_pull`, `find_pull_by_head`, `merge_pull`, `create_webhook`. `GithubProvider` (reqwest,
  timeout dari settings `git.timeout_seconds`). Base URL dari koneksi → tes memakai server GitHub
  palsu (`tests/support/fake_github.rs`).
- **Repo terhubung**: `repos` + `connection_id`, `full_name` (`owner/name`, diturunkan dari URL),
  `webhook_id`, `webhook_error`, `last_event_at`. Repo GitHub otomatis tertaut ke koneksi GitHub
  workspace saat dibuat/diubah (atau lewat tombol "Hubungkan"); server mencoba memasang webhook
  (`POST /repos/{o}/{r}/hooks`, URL `{public_base_url}/webhooks/github/{connection}`), gagal →
  instruksi pasang manual (URL + secret) di halaman Git provider.
- **Webhook** `POST /webhooks/github/{connection_id}` (tanpa sesi, dikecualikan dari CSRF, JSON):
  verifikasi `X-Hub-Signature-256` (HMAC-SHA256, constant-time) sebelum parse body; ≤ 1 MB.
  Event: `ping`, `pull_request`, `check_run`, `check_suite`, `status`. Selain itu 202 diabaikan.
  Signature salah → 401; koneksi tidak dikenal → 404.
- **PR** (`pull_requests`): repo × nomor unik; tiket (nullable), judul, URL, head/base branch,
  head sha, `state` (`open`|`draft`|`closed`|`merged`), `ci_state` (`none`|`pending`|`success`|
  `failure`), `checks` jsonb `[{name, state, url}]` per head sha, `additions`, `deletions`,
  `author`, `merged_at`. Tiket ditautkan dari nama branch (`ag/KSR-12-…` → kode tiket, termasuk
  alias) atau kode di judul PR.
- **Gate** (`services::tickets::gates`): `pr_open` = ada PR tiket yang belum ditutup tanpa merge;
  `prs_merged` = ada PR dan semua PR yang belum ditutup sudah merged (multi-repo = semua repo);
  `ci_green` = semua PR terbuka/merged punya CI `success` dan semua *check wajib* project (bila
  diatur) lulus.
- **Webhook → stage**: setelah PR/CI berubah, tiket yang stage-nya aktif, keluar `auto`, tanpa job
  terbuka, dan semua gate kini terpenuhi diselesaikan otomatis atas nama executor job terakhir
  stage itu (`stages::complete`).
- **Konvensi git project** (kolom `projects.git` jsonb, izin `AdministerProject`): pola branch
  (`ag/{kode}-{slug}`, variabel `{kode}` `{slug}` `{tipe}`), gaya commit (Conventional/bebas),
  bahasa commit/PR/komentar kode, hasil kode (`manual` | `pr`), mode merge (`manual` |
  `auto_on_review`), wajib CI hijau + daftar check wajib.
- **Job** (`JobSpec`): + `base_branch` (branch default repo), `git` (`GitSpec`: `code_output`,
  `commit_style`, bahasa), branch dari pola project. Runner: worktree dari `origin/<base>` (fetch
  dulu; fallback base lokal, lalu HEAD). Hasil `pr`: setelah commit → `git push -u origin <branch>`
  (kredensial git lokal executor) → `POST /api/runner/jobs/{id}/pull-request` → server membuka PR
  lewat provider (atau mengembalikan PR yang sudah ada untuk branch itu) dan menautkannya ke tiket.
  Semua sebelum `finish`, jadi gate `pr_open` sudah terpenuhi saat stage diselesaikan.
- **Mode merge otomatis**: approve stage ber-persona `reviewer` (Code Reviewer) di project dengan
  `auto_on_review` → setelah commit, PR terbuka tiket yang CI-nya hijau di-merge lewat provider
  (squash), hasil dicatat sebagai event tiket; gagal → notifikasi + event, tiket tetap maju.
- **Sinkron aturan via PR**: `agentgate rules sync` → branch `agentgate/sync-rules` + commit →
  push → `POST /api/cli/rules/pull-request {project, repo}` → server membuka PR "Update aturan
  Agent Gate" (atau mengembalikan yang sudah terbuka). Tanpa koneksi provider → instruksi manual.
- **Batas job paralel** (utang M5): runner memakai `Slots` (`max_parallel` dari `RunnerInfo`):
  job siap di atas batas antre lokal dan dimulai saat slot kosong. Server menolak `start` bila
  runner sudah menjalankan `max_parallel` job (`job-runner-busy`, 422); runner mengantre ulang.
- **UI**: Pengaturan → **Git provider** `/w/{slug}/settings/git/{panel}` (subpage E: Cloud, Versi
  perusahaan, Repo terhubung; dialog Hubungkan); Pengaturan project → **Konvensi git**
  `/w/{slug}/p/{KEY}/settings/git/{panel}` (Konvensi git, Hasil kode & merge, Gate CI; env/deploy/
  jalur "segera"); tab project **Pull request** `/w/{slug}/p/{KEY}/prs` (stat, tab Semua/Terbuka/
  Merged, datatable); tab tiket **PR & CI** `/w/{slug}/t/{code}/pr`; badge PR di header tiket dan
  kartu board. Komponen baru: `pr_state`, `ci_state` (badge) di `/_dev/ui`.

## Global Constraints

- Aturan M1–M5 tetap (UUID v7, `timestamptz`, enum text + CHECK + tes `EnumIter`, 404 lintas
  workspace, PRG, Fluent "Anda", audit di transaksi yang sama).
- Token provider tidak pernah tampil lagi setelah disimpan dan tidak masuk log (`Debug` manual).
- Webhook diverifikasi sebelum body di-parse; tidak ada data workspace lain yang bisa disentuh
  lewat id koneksi.
- Tidak ada panggilan jaringan ke GitHub asli di tes.
