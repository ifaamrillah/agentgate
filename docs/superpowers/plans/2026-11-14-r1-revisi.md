# R1 Revisi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** menerapkan semua baris berlabel **R1** di `docs/REVIEW-AKHIR.md` §3.0 (keputusan pemilik
produk 2026-11-14). Branch `feature/r1-revisi` dari `staging`.

## Keputusan desain

- **Satu migrasi** `m20261126_000001_r1_revisi` untuk semua perubahan skema R1 (kompatibel dengan kode
  rilis sebelumnya: hanya tabel/kolom baru nullable atau ber-default, CHECK diperluas lewat
  `extend_check`, backfill tabel kecil).
- **Bukti manual gate** = tabel baru `manual_evidence` (bukan baris `job_evidence`, yang wajib bertanda
  tangan runner dan append-only). Anggota dengan `EditProject` mengunggah screenshot (PNG/JPEG/WebP,
  dicek dari isi), log (teks/JSON/XML) atau teks langsung untuk gate `tests_passed` atau
  `screenshot_exists` stage sekarang. Status `pending → approved | rejected`; yang memutuskan adalah
  approver stage (atau, bila stage tanpa approver, siapa pun yang boleh mengubah tiket, sama dengan
  approve/reject stage). Gate terpenuhi oleh evidence runner **atau** bukti manual `approved` sejak
  tiket masuk stage. Setiap langkah: audit (`evidence.submitted|approved|rejected`), riwayat tiket
  (`evidence_submitted`, `evidence_decided`), notifikasi approver (`evidence_review`). Label "Manual"
  (badge `warn`) vs "Ditandatangani runner".
- **Merge**: `GitSettings.merge_mode` tetap (`manual` default, `auto_on_review`) + field baru
  `merge_method` (`squash|merge|rebase`, default squash) dipakai provider. Mode manual: approve stage
  Code Reviewer menandai PR terbuka tiket `merge_ready_at`; PR dengan tanda itu + CI hijau menampilkan
  tombol **Merge** (izin `EditProject`) di tab PR & CI tiket, merge lewat provider + audit
  `pull_request.merged`. Migrasi mengubah project `auto_on_review` yang ada ke `manual`.
- **Client OAuth**: kolom `oauth_clients.approved_at` diisi saat grant pertama dibuat (consent atau
  persetujuan device). `exchange_code`/`refresh`/device token menolak client tanpa `approved_at`
  (`unauthorized_client`). Langkah cleanup baru `oauth_clients`: client tanpa persetujuan, umur > 24 jam,
  bukan client CLI bawaan → dihapus. Backfill: client yang punya grant dianggap disetujui.
- **Runner**: kolom `runners.team` (runner tim), `runners.auto_claim`, `runners.max_parallel`.
  Runner pribadi memakai pengaturan pribadi (`runner_prefs`, auto-ambil default mati). Menandai runner
  sebagai runner tim (Owner/Admin bawaan) menyalakan auto-ambil (default nyala) dan batas paralel per
  runner. Panel "Runner tim" + pengaturannya hanya Owner/Admin bawaan; anggota lain melihat runner
  sendiri, antrean, izin, pengaturan pribadi, drift, instal CLI. Ambang online `ONLINE_SECONDS = 90` dan
  `HEARTBEAT_SECONDS = 30` di `agentgate_core::runner` dipakai server (model, SQL Status sistem, AI
  Office lewat `is_online`) dan CLI.
- **`manage_knowledge`**: varian `Permission::ManageKnowledge` + CHECK + backfill Owner/Admin bawaan.
  Semua pemakaian `ManageTicketSettings` di area knowledge diganti. Approve usulan tetap pemilik
  knowledge atau `AdministerProject`.
- **API & webhook**: kolom `api_tokens.rate_limit_per_minute` (NULL = default 600). Owner/Admin bawaan
  mengubahnya dari halaman API (rentang 60–6.000, audit `api_token.updated`). Webhook yang dinonaktifkan
  otomatis bisa diaktifkan ulang Owner/Admin (tombol "Aktifkan ulang" + alert penyebab).
- **Backup**: logika retensi di `deploy/backup/retention.sh` (fungsi murni: daftar nama dump + waktu
  sekarang → daftar yang dihapus): simpan semua dump ≤ 14 hari + dump pertama setiap bulan untuk 6 bulan
  terakhir. Diuji `bin/tests/backup_retention_test.sh` (ikut `bin/ci`).
- **Logo SVG**: sanitasi allowlist (quick-xml) elemen/atribut SVG; buang script, `on*`, `foreignObject`,
  href eksternal (termasuk `use`), DOCTYPE/entity/PI, CSS `url()` eksternal/`@import`. Hasil sanitasi
  yang disimpan; disajikan dengan `Content-Type: image/svg+xml`, CSP `default-src 'none'; style-src
  'unsafe-inline'`, `nosniff`. Tes XSS.
- **Sentry**: server memakai crate `sentry` (panic + event `tracing` level error), `send_default_pii =
  false`, `before_send` membuang cookie, header `authorization`/`cookie`/`x-runner-*`, body request, query.
  Browser: reporter kecil `sentry.js` (tanpa SDK pihak ketiga, CSP `script-src 'self'` tetap) yang
  mengirim `window.onerror`/`unhandledrejection` ke endpoint envelope Sentry; DSN publik lewat `<meta>`.
  CSP `connect-src` ditambah host Sentry hanya bila `SENTRY_DSN` diisi. Dokumentasi `docs/admin/`.
- **Tombol `success`**: varian baru di komponen `button` + CSS token `--ag-success-btn` (terang/gelap,
  kontras ≥ 4,5:1 dengan teks putih). Approve (stage, bukti manual, usulan knowledge, skill pack, draft,
  mockup) memakai `success`; Reject memakai `danger`.
