## 1. JQL

- AST `Expr = Clause | Not | And | Or`; `Query { expr: Option<Expr>, order }`. Tata bahasa:
  `or := and (OR and)*`, `and := unary (AND unary)*`, `unary := NOT unary | "(" or ")" | clause`.
  Presedensi `NOT` > `AND` > `OR`. Kedalaman kurung maks. 10, syarat maks. 20.
- Error = `JqlError { code, args }` (kunci Fluent `jql-…`, argumen `name`, `max`, `list`);
  `message()` lewat `common::i18n::text`. `ERROR_CODES` dites kontrak i18n. Petunjuk field di
  bantuan juga ke Fluent (`jql-field-<nama>`).
- Saran: `jql::suggest_context(prefix)` (tokenizer longgar, mesin keadaan: field / operator /
  nilai / sambungan / ORDER BY) → `GET /w/{slug}/search/advanced/suggest?q=<teks sebelum kursor>`
  membalas JSON `{ partial, items: [{ insert, label, hint }] }`. Nilai dari DB untuk project, stage,
  assignee (+`currentUser()`), type, sprint (+`openSprints()`), label, fixversion, component;
  status/priority tetap. Nilai berspasi dikutip.
- JS `jql-core.mjs` (murni, tes node: sisip saran, navigasi daftar) + `jql-suggest.js` (combobox
  ARIA: `role=combobox`, `aria-expanded`, `aria-activedescendant`, listbox; ↑/↓, Enter/Tab
  memilih, Esc menutup; debounce 120 ms).

## 2. WIP

- `stages::move_in` mengecek batas WIP stage tujuan (versi aktif workflow tiket): jumlah tiket
  aktif project di stage itu (tidak termasuk tiket ini, sampah, dibatalkan) ≥ batas → error
  `ticket-wip-full` (argumen stage, batas). Berlaku untuk board (drag/menu), ubah status di
  detail, API `/api/v1`, MCP, dan sinkron Jira (semua lewat `move_in`). Approve/keputusan/lompat
  Admin tidak dicek (alur gate, bukan pindah kartu).
- Paksa: `stages::move_over_wip` (`AdministerProject`, alasan wajib) → pindah + event riwayat
  berisi `wip_override` + audit `ticket.wip_overridden`. Form `POST …/t/{code}/move-over-wip`.
- Board: kepala kolom memakai hitungan project (sama dengan penegakan), `data-wip-full`. JS
  menolak drop ke kolom penuh tanpa kirim (kartu tetap/kembali ke posisi semula) dan menampilkan
  pesan; Admin mendapat dialog "Paksa pindah" berisi alasan. Server tetap otoritas: gagal dari
  board → redirect kembali ke board + flash error berteks (Flash `text` hasil Fluent).
- API/MCP: 422 dengan pesan Indonesia yang jelas.

## 3. Roadmap per epic

- `?group=sprint|epic` (seg). Mode epic: baris epic (tipe `epic`) dengan batang rentang anak
  (min mulai – maks selesai; tanpa anak ber-rentang → rentang epic sendiri), progres = anak
  selesai / anak; tombol buka/tutup per epic (`?open=` daftar kode, server-side, `aria-expanded`),
  grup "Tanpa epic". Panah `blocks` antar baris tampil; anak yang tertutup dipetakan ke baris
  epic-nya. Fungsi murni pengelompokan + rentang di `planning::timeline` (tes unit).
- Teks tooltip roadmap pindah ke Fluent (utang M9).

## 4. Panel samping tiket

- Isi Ringkasan dipindah ke partial `tickets/_summary.html`; `show.html` dan `panel.html` sama-sama
  meng-include-nya (tidak bercabang).
- `GET /w/{slug}/t/{code}` dengan header `X-Ticket-Panel: 1` (+ `HX-Request`) → partial panel;
  tanpa header → halaman penuh seperti sekarang.
- `ticket-panel.js`: tautan `[data-ticket-peek]` (judul kartu board, daftar, backlog) dibuka di
  `<dialog>` modal native (fokus terkunci, latar inert) di sisi kanan, `history.pushState` ke URL
  tiket; Back/Esc/tombol tutup/klik latar menutup (tutup = `history.back()` bila panel yang
  mendorong history). Forward membuka panel lagi. Fokus kembali ke tautan pembuka. Klik dengan
  modifier / tengah tetap tab baru. Kepala panel: kode + status, "Buka halaman penuh", tutup.
- Lebar 640px desktop (acuan prototype `.drawer`), 390px = layar penuh.

## 5. Kanvas workflow

- `workflow-core.mjs` (murni, tes node): baris (stage paralel bergabung dengan baris
  sebelumnya), posisi node, sisi maju antar baris, sisi gagal (`fail_to`, rute di kanan, putus-
  putus merah + label), kotak kelompok paralel, ukuran kanvas, kamera (zoom di titik, batas zoom,
  pas ke layar).
- `workflow-canvas.js`: SVG garis + node HTML `<a>` (`?stage=key`) di lapisan dunia yang
  di-transform; geser (pointer), zoom (roda + tombol + / − / Pas, keyboard + − 0 dan panah),
  pinch; posisi kamera disimpan sessionStorage per workflow; node terpilih disorot.
- Server: JSON graf di `<script type="application/json">` (label sudah diterjemahkan).
  Sakelar Kanvas/Daftar (`?view=list`, disimpan); daftar vertikal lama tetap (keyboard, mobile,
  tanpa JS = fallback di dalam kanvas).
- **Izin aksi berbahaya per stage**: `Stage.danger: BTreeMap<aksi, Level>` (override persona;
  kosong = ikut persona), divalidasi (aksi dari `DANGER_ACTIONS`), YAML `izin_bahaya`, form stage
  (select per aksi: Ikuti persona/Izinkan/Tanya/Blokir), dipakai `JobSpec` job tiket di stage itu.
