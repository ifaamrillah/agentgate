**Goal (spec "Selesai bila"):** production bisa jalan (image + Compose di VPS, migrasi terpisah, backup,

Status sistem).

## Keputusan desain

- **Realtime runner lewat `LISTEN/NOTIFY`.** Trigger Postgres pada `jobs` (insert/update) dan
  `job_permissions` (insert/update) memanggil `pg_notify('agentgate_jobs', workspace_id)`. Satu
  `PgListener` per proses (`services::realtime::Hub`, disimpan di `ctx.shared_store`) menyiarkan id
  workspace lewat `tokio::sync::broadcast`. Socket runner bangun saat ada notifikasi workspace-nya,
  dengan tick cadangan 30 dtk (sebelumnya polling 2 dtk) untuk validasi sesi dan notifikasi yang hilang
  saat listener tersambung ulang. Trigger di database berarti perubahan dari worker/task ikut terkirim.
- **Uji beban** = tes `#[ignore]` + example yang membuka N pendengar dan M notifikasi, mencatat p50/p95
  latensi fan-out; hasil di `docs/benchmarks/2026-11-14-listen-notify.md`.
- **Storage** staging/production = S3 (`storage_aws_s3`) dari env `S3_*`. Purge workspace mengumpulkan
  semua key storage milik workspace (lampiran, logo, evidence, ekspor, impor, backup aturan) sebelum
  transaksi hapus, lalu menghapus berkasnya setelah commit (gagal hapus berkas hanya dicatat).
- **Hardening**: rate limit DCR `/oauth/register` per IP (tabel `api_rate_limits` yang sudah ada); kode
  otorisasi dibatalkan setelah verifikasi PKCE gagal; HSTS; `statement_timeout` role database di skrip
  init produksi; cek SSRF semua URL keluar (webhook, Jira, GHES) memakai validasi IP setelah resolve.
- **Observability**: `/_health` (liveness), `/_readiness` (DB + queue) publik; `/_metrics` format
  Prometheus hanya dengan `Authorization: Bearer $METRICS_TOKEN` (tanpa token = 404). Metrik: request
  per route/status + histogram durasi, job queue per status + umur tertua, pool DB, login gagal, pendengar
  realtime. Tanpa dependensi baru (teks Prometheus ditulis sendiri). Error tracking (Sentry) menunggu DSN
  dari pemilik.
- **Status sistem** (`/system`): halaman instance, hanya untuk email di env `SYSTEM_ADMIN_EMAILS`
  (bukan Owner workspace, karena data instance lintas tenant). Panel: Ringkasan, Layanan & antrean,
  Database & storage, Backup (riwayat dari tabel `system_backups` yang diisi skrip backup), Error (job
  queue gagal 24 jam). Pengaturan jadwal/bucket backup tetap env (tanpa form).
- **Deploy**: `docker/prod/Dockerfile` multi-stage (toolchain dari `rust-toolchain.toml`, Tailwind di
  builder, runtime Debian slim non-root, `HEALTHCHECK /_health`), image `agentgate-rs-server:<sha>`.
  `deploy/compose.yaml`: `migrate` (one-shot), `web`, `worker` (`start --worker --scheduler`), `db`
  pgvector, `s3` SeaweedFS, `caddy` (TLS otomatis, WebSocket, domain preview terpisah), `backup`
  (pg_dump terjadwal → S3 di luar VPS + baris `system_backups`). `deploy/.env.example`. Nama project
  Compose `agentgate-rs-prod`.
- **CLI**: `dist-workspace.toml` (cargo-dist, installer shell + powershell + Homebrew, checksum
  SHA-256, attestation) + `.github/workflows/release.yml`; server menyajikan `/install` (halaman publik),
  `/install.sh` dan `/install.ps1` (redirect ke installer di GitHub Releases dari env `CLI_RELEASE_URL`;
  tanpa env = 404 dengan pesan). `agentgate self-update` menjalankan ulang installer resmi. `bin/release-cli`
  membangun binary Linux lokal + `sha256` tanpa publish.
- **Dokumentasi**: `docs/admin/` (deploy, konfigurasi env, operasi, backup/pulihkan, upgrade, keamanan) dan
  `docs/panduan/` (mulai cepat untuk user).
